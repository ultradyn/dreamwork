The shape that survives all five

Entry and identity separate — finding 1's only honest answer. Per-entry attributes live on the entry; task is permanent identity pointing at it, so #138 and #156 share one body that cannot disagree with itself.

entry(entry_id PK, state open|landed, title, body verbatim,
      priority NULL, priority_rank NULL, type NULL, origin NULL, source_line)
task (id PK, entry_id -> entry, ordinal)
priority + priority_ranktwo columns: your words kept verbatim, plus a derived rank so P0/P1 sorts with P0 instead of after it
type NULLpopulated only from unambiguous forms; the migration reports what it could not read. #339's ruling: a misdetected value is worse than none
origin NULLNULL means no marker was ever written; unknown means it was audited and recorded as unknown

The four decisions

All four are the same question in different clothes: how much of today's looseness is a feature to preserve, and how much is an artefact to resolve at cutover? The recs lean the same way each time — preserve, because the looseness is yours and the schema is new.

S1 · Combined entries. Keep them, with the entry/task split above? Or split #138/#156, #250/#251, #292/#293 into single-id entries once, before migrating, and forbid new ones?
Rec: keep. Forbidding is simpler forever but edits three of your existing entries, and combining is a thing you did on purpose — two ids, one piece of work. The cost is that every consumer joins one table.
S2 · Compound bands. Does P0/P1 stay legal after cutover, or is it an artefact to resolve to one band as each entry is touched?
Rec: stays legal. P0/P1 says something a single band cannot — genuinely urgent, not yet certain which. The rank column makes it sort correctly without editing your words.
S3 · The 60 unmarked origins. Leave NULL permanently as "predates the convention, never audited"? Or backfill to explicit unknown so the column can be NOT NULL?
Rec: leave NULL. Backfilling asserts an audit that did not happen, and the distinction is exactly the one your own #289 rule protects. NOT NULL is not worth a false claim about 60 entries.
S4 · Is type a closed set? Freeze the ~10 real values at cutover, or keep it free text with NULL for unread?
Rec: free text with NULL. Closing the set means the migration must classify all 237 entries correctly, and finding 5 says it cannot. A NULL you can see beats a category you cannot trust.
