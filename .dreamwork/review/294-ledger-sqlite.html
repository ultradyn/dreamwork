The script — staged, readable, each stage prints exact counts
dreamwork tasks migrate --dry-run            # parse + report; writes nothing
dreamwork tasks migrate --report <path>      # full report to a file
dreamwork tasks migrate --backup <dir>       # copy tasks.md + DB, fsync
dreamwork tasks migrate --import             # atomically populate the store
dreamwork tasks migrate --verify             # replay, diff, exit non-zero
dreamwork tasks migrate --cutover            # the lease + rename + notice
dreamwork tasks migrate --rollback <backup>  # restore file; never a legacy writer

Each stage exits non-zero on any surprise, so a human reading the output sees what the import will do before it does it. The script uses the production parser (#352's unified module once it lands), never a regex of its own. --dry-run reports entry/id counts derived and asserted, the band/type/origin histograms, every unreadable entry, every "blocked on" phrase not convertible to an edge, and a digest per entry so a later --import proves it carried the same bytes.

atomicityimport runs inside one BEGIN IMMEDIATE … COMMIT in the live store, because #264 F6 measured the receipt FK can only exist in one database file. A failed import leaves the store untouched
verifyreplays the import into a temp table, diffs row-for-row including digests, and re-derives the open/landed id sets from the store and asserts they equal the parser's pre-rename sets
the id seedsqlite_sequence is seeded from the Markdown Next id and the seed is asserted == MAX(id)+1 — a header drifted below reality stops the migration, it does not mint a colliding id
The decisions worth rivals — an IGC

Context: the ledger moves from one committed Markdown file (single writer by convention, 578 commits of history) to one gitignored SQLite store shared with #263's journal. The migration must not lose an id, an entry, or a burndown point, and must roll back without restoring the hazard it removed. Goals are binary. G1 two writers never mint the same id · G2 imported & future ids never collide · G3 the seed is verified, not trusted · G4 the sequence survives a crash mid-file · G5 rollback restores data without a legacy writer · G6 a stale agent self-heals · G7 the script is human-readable.

decisionAllsurvivorwhat refutes the rivals

M2 · cutover & the freeze✔A exclusive lease + #263 lane-H gate; flip readers after #352B "big bang" with no freeze — refuted on G5+G6: a concurrent writer mutates tasks.md mid-import and the backup no longer matches; a stale agent keeps writing with no notice. M3 · git history✔A first-sight arrivals+landings, actor='migration:git'B import nothing, burndown-before-cutover stays on git — refuted: a store whose burndown is flat-before-cutover silently understates history on any clone that doesn't walk git. C reconstruct every cause from prose — refuted: the Markdown never recorded intra-life causes, so this is fabrication
M5 · deprecation + notice✔A rename to .deprecated (YAML block) + one-line tasks.md shim with a #458 noticeB rename, no shim, rely on re-init — refuted on G6: an agent that never re-initialises (the #458 case) finds the file gone and silently loses work. C keep Markdown authoritative — the dual-write shadow, refuted again
The most important refutation is M2-C. A "shadow run" that keeps Markdown authoritative while mirroring into the store is the second derived truth your #294 amendment — "no second derived truth" — exists to forbid, under another name. It also never reaches a decision to flip, so a human cannot read when it is safe to stop shadowing.
Cutover copies #263's own sequence — it does not invent a second gate

The hazard is the same as #263's (two writer generations must never overlap), so the cure is the one already approved there:

1acquire an exclusive cutover lease on the target
2freeze every writer — coordinator, watch.py, any lane — and prove none owns the generation. This is the "mixed-writer freeze". It is a lease + the version gate, not a pkill
3run dry-run, backup, import, verify under the lease
4flip the readers (after #352 unifies the parser): ledger_series, parse_ledger, the /tasks badge, the status section all become store queries
5rename tasks.md → tasks.md.deprecated + leave the notice shim
6–7write the cutover watermark; release the lease. New writes go through dreamwork tasks file|grab|cycle

Mixed-version fail-closed is #263 lane H, consumed not reinvented. Until H lands, an old watch.py could keep writing tasks.md after cutover and the store would never know. Cutover is sequenced after lane H, full stop.
