# #328 lane dogfood — the planned UI seam had not landed

The task correctly treated #281 as landed for the shared data seam:
`TaskRepository.records()` feeds `/tasksdata`, and `/tasks2` could compose that
without a parser or database. The plan also said #281 would leave reusable
`taskRow` and `buildTaskDetail` client helpers, but `eddf2f6c` was explicitly
“Task 1” and changed only the repository projection/server surface; neither UI
helper exists in the landed tree. The #328 brief therefore mixed a real landed
dependency with two planned-but-unlanded seams.

The lane stayed inside the authorised result: `/tasks` was not changed, and
`/tasks2` renders its own row/detail composition over the one endpoint. A future
brief that depends on a named seam should verify the symbol exists at dispatch,
not infer all plan deliverables from the parent task's landed state.

One related scope wrinkle remains for the coordinator: `watch-design.md` says a
new width exception should be documented, while `Lane-owns:` excluded that file.
This lane did not widen ownership silently.
