## The thing worth carrying: all three bugs were invisible to an end-state check

They arrived as three unrelated reports and they are one shape. In each, the
page ended exactly where it should and the frames in between were the defect:

| | what was right | what was wrong |
|---|---|---|
| #191 | the neighbour ends in its new place | it got there in **two positions** |
| #159 | the confirmation is on screen | it was there on the **first** frame |
| #169 | the neighbour ends in its new place | it **snapped** the last 20px |

So all three guards assert the same quantity — **the number of distinct
intermediate values** — and none of them assert a mechanism. That distinction
is already this repo's rule (`states.mjs`: a card carried by an animated height
above it travels perfectly with no transform of its own), and it is what let
the #169 check survive being right: it never says "there is a transform", only
"it visited 45 places and it was at the last one when its travel ended".

**The corollary is the useful half.** If a report is about how something moves,
an end-state assertion cannot fail on it, and neither can "did it move". Write
the check against the middle or do not write it.

## A guard's WINDOW is part of its assertion

`regroup.mjs` has driven the #191 gesture through the real UI since #104 — the
right page, the right click, the right card — and was green over the bug for a
day, because it traces 5.2s and `holdRerenderUntil` is 1.6s. The tick's own
regroup travels the neighbour at ~2s, so every "it slid" assertion passed over
a teleport that had happened a second and a half earlier.

Nothing about the driver was wrong. **Any path that holds the tick has a window
inside which it must be measured, and a guard that outlasts the window is
measuring the recovery rather than the feature.** `morph.mjs` traces 1400ms and
adds the assertion that makes it self-proving: the card node was never replaced
across the window (`card.innerHTML = …` keeps the node, a tick's list swap does
not), so whatever moved, the morph moved.

## The FLIP's measurement window is a layout contract, not a style one

#169's trap, and it generalises past #169. `regroupCards` measures the new rect
in the same tick as the mutation. Anything that changes layout *asynchronously*
— a CSS transition on `padding`, on `height`, on a child's box — hands it a
start-of-transition rect. The FLIP then plays perfectly to a height the element
never reaches and snaps the difference when the inline height is cleared.

So: **inside a FLIP's measurement, layout lands instantly; only the FLIP
animates.** Injecting `transition:padding .35s` left the neighbour 20px short
at 950ms — and tripped exactly one check out of sixteen. The other fifteen,
including "it travelled continuously over 45 positions", passed on it.

## Two smaller ones

- **#159's departure was not missing, it was elsewhere.** The task said "check
  the departure too" and the honest answer was that the two hand-clears are
  *retractions* — the page withdrawing a claim that has become false — while
  the real departure is the panel's, which already drifts away on the same soft
  blur it arrived on. A false confirmation that fades slowly is a false
  confirmation that is quieter. Recorded in the doc rather than animated.
- **Do not revert a RED injection with `git checkout`.** I injected a deliberate
  bug into `watch.py`, confirmed the guard went red, and reverted with
  `git checkout -- watch.py` — which also destroyed 51 lines of uncommitted
  #169 work in the same file. The injection had been made by a script; the
  revert should have been the inverse script. **Revert an injection with the
  inverse of the injection, never with a whole-file operation, whenever other
  uncommitted work shares the file.**
