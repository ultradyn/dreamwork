## 1. Suite behaviours and contracts (observed)

### 1.1 Skill craft (`writing-great-skills`)

- Root virtue: **predictability of process**, not output tokens.
- **Model-invoked** vs **user-invoked** (`disable-model-invocation: true`): context load vs human cognitive load.
- Progressive disclosure, completion criteria, anti-negation, no-op pruning (full vocabulary in `GLOSSARY.md`).
- Many suite skills are **user-invoked only** — an autonomous loop cannot “see” them unless a human types the name or a **router** skill (`ask-matt`) is used.

### 1.2 Domain model (`domain-modeling`, setup)

- **`CONTEXT.md`** (+ optional `CONTEXT-MAP.md`) is the ubiquitous language.
- **ADRs** under `docs/adr/` (or mapped paths).
- `setup-matt-pocock-skills` writes `docs/agents/{issue-tracker,domain,triage-labels}.md` and an `## Agent skills` block into `CLAUDE.md` or `AGENTS.md` — **repo-local configuration**, not machine-global.

### 1.3 Interview / decision (`grilling`, `grill-me`, `grill-with-docs`)

- One question at a time; recommended answer offered; wait for human.
- Facts: look up; **decisions**: always human.
- `grill-with-docs` persists into `CONTEXT.md`/ADRs; `grill-me` is stateless (no codebase).

### 1.4 Work intake (`triage`, `to-spec`, `to-tickets`, `wayfinder`)

- **Triage state machine** on the configured issue tracker:
  `needs-triage` → `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix` (+ category `bug`/`enhancement`).
- Tracker may be GitHub (`gh`), GitLab (`glab`), or **local markdown under `.scratch/`**.
- AI comments **must** start with `> *This was generated by AI during triage.*`
- `ready-for-agent` posts an **agent brief**; implementers are expected to pick those up.
- `to-tickets` / `wayfinder` break work into tracer-bullet tickets with blocking edges.

### 1.5 Build loop (`implement`, `tdd`, `code-review`, `diagnosing-bugs`)

- `implement`: use `/tdd` at pre-agreed seams → typecheck → full suite → `/code-review` → commit.
- `tdd`: red→green; **seams confirmed with human before tests**; vertical slices; CONTEXT.md vocabulary.
- `code-review`: Standards + Spec axes (often sub-agents).
- `diagnosing-bugs`: tight red-capable feedback loop before hypothesising.

### 1.6 Continuity (`handoff`)

- Compacts session to a **handoff document in the OS temp directory** (not workspace).
- References existing artifacts; suggests skills; redacts secrets.
- Different grain from Dreamwork’s on-target `.dreamwork/` + PreCompact hooks.

### 1.7 Router (`ask-matt`)

- User-invoked map: which skill for which situation (grill → domain → tickets → implement, etc.).
- Does not auto-fire user-invoked skills; **human remains the index** for most of the suite.

scope gate, dashboard-only human asks, coordinator-only `tasks.md`, no private plugin queues, subagents never `attn`, stdlib/offline watch constraints.

### 3) Grilling: serialize the interview thread only

**Problem:** Dreamwork often has many open `questions.md` entries. Matt grilling requires **one question at a time** within an interview.

**Design:**

| Concept | Definition |
|---------|------------|
| **Grill session** | Durable identity `grill:<uuid>` (or `grill:<slug>`) owned by the bridge |
| **Session state** | Machine-local or target-local small JSON under existing machine-local plugin pattern (`~/.config/dreamwork/matt-skills/<target-slug>/grill-sessions.json`) — **not** a second ask channel; optional. Minimum viable: encode state in the single active grill question’s metadata/body conventions |
| **Active thread** | At most one grill session in `active` state per target |
| **Open grill question** | Exactly one `questions.md` entry tagged as grill (title prefix or structured note) while session active |
| **Unrelated questions** | Remain open and answerable; grill serialization **does not** block other P1s |

**Lifecycle:**

1. **Start** (command `matt-grill-start` or task-start design profile): create session; post first decision as one open question with recommended answer in body; session=`active`.
2. **Answer arrives** (dashboard/watch): loop applies answer; bridge **next** opens the subsequent grill question (or closes session if shared understanding reached). Prior grill Qs move to Answered/folded like any question.
3. **Pause:** session=`paused`; no next Q; human can answer other open questions freely.
4. **Cancel:** session=`cancelled`; no further auto-open; leftover open grill Q can be closed with note.
5. **Restart:** new session id; never silently resume a cancelled id as if continuous.

**Coexistence rule:** “One-at-a-time” applies **inside** the active grill session’s question chain only — not “only one open question in the whole file.”

### 5) Invocation semantics (must not conflate)

| Code | Meaning | Autonomous loop? |
|------|---------|------------------|
| **(a) Invoke model-invocable skill** | Skill has live description / no `disable-model-invocation`; agent may fire by description or name | Yes, when applicable and loaded |
| **(b) Process profile** | Documented steps *inspired by* a user-only skill (e.g. implement→tdd→review), executed as ordinary Dreamwork prose procedure | Yes — this is Dreamwork behaviour, not a skill fire |
| **(c) Ask human to invoke user-only command** | questions.md or command confirmation: “type `/implement` / `/grilling` …” | Human must act |

**`ask-matt`:** user-invoked router (`disable-model-invocation: true` on installed copy).
- **Not safe** as autonomous tick router: no description means the model is not supposed to discover it; firing it from the loop would be a **category error** and would still not fire other user-only skills.
- **Safe:** human-invoked orientation; or loop **quotes** its map as static reference (b) without claiming skill invocation.
- **Authority:** none beyond read; no external writes.

**`tdd` / `diagnosing-bugs` / `grilling` / `code-review`:** treat by frontmatter on the **installed** copy: if model-invocable → (a) allowed; if user-only → (b) profile or (c) ask. Installed mix: e.g. `tdd` often model-invocable; `implement` user-only — bridge tables the observed install, not upstream assumptions alone.
