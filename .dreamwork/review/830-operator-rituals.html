INFERRED — build just launch-lane: one accepted brief source → checked worktree → governed launch.

VERIFIED — recurrence and cost. The transcript contains 115 just dispatch-lane launches and 188 worktree-add invocations. The measured current shape takes about 15 operator-authored plumbing lines per lane. The latest observed dispatch is representative:

INFERRED — rank calculation. 115 launches × ~15 lines = ~1,725 repeated operator actions; that is the largest observed frequency × stated-cost burden.

INFERRED — contract. Take a task id, lane/branch, agent, and a human-authored brief head; obtain and report the current base; create the worktree; append the canonical boilerplate; validate the exact final brief; persist its digest; launch through the existing dispatcher; and return a durable attempt id plus the real runner result. It must not invent ownership, tests, agent policy, or prose.

VERIFIED — failure this must close. #828 measured a @glm52 dispatch that exited immediately while leaving a worktree, branch, and zero commits; retrying then refused because the brief corpus identity was occupied. Its exact reported refusal was brief corpus name 660-glm-660ruling.md already belongs to another dispatch. The current dispatcher persists before execvp and cannot report a runner that exits after exec.

INFERRED — what would make this tool wrong. It is wrong if a runner refusal is shown as a launch, if it erases a possibly-live corpus identity just because a process is not immediately observable, or if it changes a retry’s brief bytes while presenting it as the same attempt. On pre-launch failure it must leave no new worktree or report the exact retained state; on post-launch uncertainty it must say unverified attempt, preserve the bytes, and require an explicit identical-digest retry/resume path.

02

INFERRED — build just land-lane: one branch → merge gate → preserve-aware retirement.

VERIFIED — recurrence and cost. There are 216 git merge --no-ff invocations. The standing merge ritual is six separate acts: merge, named tests, lint, complete WARN-row comparison, the repo-wide guard list, and worktree preserve-check. Its stated burden is therefore 216 × ~6 = ~1,296 operator actions before counting cleanup.

git merge --no-ff <lane>
just pytest <named tests>
python3 lint.py                 # compare full WARN rows, not only trailer
python3 dev/repo_wide_guards.py list
just pytest $(python3 dev/repo_wide_guards.py list)
git -C .worktrees/<lane> status --porcelain --ignored

VERIFIED — safety evidence. The session recorded 141 raw git worktree remove invocations. After reap-lane landed, a later twelve-hour slice still has 60 raw removes versus 14 just reap-lane calls. The current reap-lane does use git status --porcelain --ignored and checks unmerged commits, but it is a separate remembered act; a raw removal bypasses it.

VERIFIED — concrete loss. The latest Merge #660 message says a completed lane was force-removed WITHOUT a preserve-check and recovered as b2ff93f2 only from the reflog. This is a recurrence with material loss potential, not a style preference.

INFERRED — contract. Require an explicit branch and named test selection; record pre-merge branch/worktree state; merge; run only the named test subset plus the generated repo-wide guard set; emit the full lint WARN rows and a baseline comparison; then call the existing reap-lane implementation, never raw git worktree remove. Stop before ledger folding and branch deletion unless their exact preconditions are separately declared.

INFERRED — what would make this tool wrong. It is wrong if it turns a missing test selection, missing WARN baseline, or unavailable guard set into a green-looking zero; if it deletes a lane after any failed gate phase; or if it merely prints a preserve warning while proceeding. On any refusal it must retain the branch/worktree and name the phase, files/commits examined, and operation it deliberately did not perform.
